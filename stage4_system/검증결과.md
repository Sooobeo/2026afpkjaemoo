# 4단계 도구 구현 검증 결과

검증일: 2026-11-13 KST  
환경: Windows, Python 3.13, 외부 Python 패키지 없음

## 1차 계산과 원자료 재현

기존 `hw/verify_plan.py`를 비메인 함수로 읽어 새 엔진의 숫자와 비교했다. 기존 출력 파일을 다시 생성하지 않았다.

- 2027·2030·2031년 기본안과 6개 연장 조건의 기존 월별·거래일 숫자 열을 0.000001만 원 허용오차로 대조했다.
- 별도 할인현금흐름 합계로 원리금을 확인하고, 0금리·가격 구간별 취득비용을 검산했다.
- 출산비 1,380·바우처 300·55개월 현금지원 1,690·휴직기여금 378·정산 유보 60·사적연금 7,000을 확인했다.
- 2029.6 총현금 증가 약 25.9438541과 유보 후 신규 배분 가능액 약 20.9438541을 구분했다.
- 6.3억 비거래 복합의 잔금 보호여유 30.542698, 2033.6 월수지 -7.538612, 2033.7 보호기준 위반을 재현했다.

발견·수정: 산전 바우처가 같은 달의 부적격 예약금 등에 적용되지 않도록 적격 진료비 한도를 분리했다. 월말·기초잔액·개별 사건을 구분하고, 첫 월급이 기초 보호자금 부족을 가리지 않게 했다.

## 2차 실행·출력·인계

계산·입력·사건·탐색 검사 31개와 CLI·출력 통합검사 8개, **총 39개 테스트가 통과**했다.

```powershell
python -m unittest discover -s tests -v
```

통합검사는 다른 작업 폴더에서의 실행, 필수 산출물 15개, 구조화된 오류와 탐색 종료 상태, 입력과 기존 참조파일의 해시 보존, 결과 해시 재현을 포함한다. 계획·실제 부분 실행과 기준일 이전 재가산 방지, 승인·고객 상환한도·미평가 상태도 확인했다.

발견·수정: 보고서가 엔진의 `builtin_` 접두사와 다른 사건 ID를 찾아 계약·잔금 요약값이 비어 있던 문제를 고쳤다. CSV와 HTML 내 JSON을 실제 계산 결과와 대조하는 검사로 다시 확인했다.

전체 실행은 **12개 대안과 110개 추가 스트레스**를 완료했다. 기본 입력 오류는 0개, 확인사항은 13개다. 확인사항은 설정·승인·증빙의 미확정을 표시하며, 숫자를 임의 확정해 없애지 않았다. 현재 소스와 생성물의 코드 해시 일치도 확인했다.

대출 탐색 명령도 실제 실행했다. 명시한 0~40,000만 원·100만 원 격자에서 6억 후보의 첫 수치 통과액을 찾았으며, 승인 미확정·노후 충분성 미평가 상태를 함께 유지했다. 이 값은 스트레스까지 포함한 매입 권고나 은행 승인액이 아니다.

## 3차 브라우저와 표현 검토

Chrome headless에서 1600×1150 크기로 로컬 HTML을 렌더링했다. 기본 2027년 안과 `candidate_63000_nontrade` 두 상태를 이미지로 확인했다.

- 대안 선택, 가격·원리금·최저 보호여유·판단 카드, 월말 현금/보호자금 그래프가 표시됐다.
- 2027년 계약일 보호여유 약 -552.3, 6.3억 비거래 복합 잔금일 약 +30.5와 연장기간 최저 약 -1,197.8이 각각 표시됐다.
- 계약·잔금 자금표와 대안별 비교표가 겹치거나 잘리지 않았다.
- 링크로 같은 대안을 다시 열 수 있도록 URL fragment를 지원한다.
- 미확인 승인·제도와 노후 충분성 미평가를 수치 통과와 구분했다.

화면 그래프는 월말 경로이며 모든 실제 일자의 지급능력을 나타내지 않는다. 날짜별 확인은 등록된 사건에 한정한다. 실제 제도·지원 적격성·대출·송금·임대차 확인과 장기 연령별 예산·노후 충분성은 결과에도 별도로 남겼다.
